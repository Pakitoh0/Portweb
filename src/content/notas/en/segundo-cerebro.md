Coding agents start every session with no memory. I kept repeating my preferences, the state of each project and how we had fixed an error the week before. The obvious way out, putting everything in a `CLAUDE.md`, filled the context and did not scale.

The success criterion was simple: **repeat myself less and never hit an already-solved error again, without filling the context**.

## The structure

It is a local Markdown Obsidian vault, with no external services or background processes:

```text
Brain/
├── 00-index.md        routing table: "if you need X, look in Y"
├── 01-perfil/         preferences (they override the defaults) and system
├── 02-programacion/   stack, conventions, testing, lessons and snippets
├── 04-proyectos/      one folder per repository
├── 06-conocimiento/   documentation and technical sources
├── hot.md             what I am working on right now
└── log.md             what was written and when
```

Every note has frontmatter with `type`, `tags`, `summary` and `updated`. The agent searches by summary and only opens what it needs. Large folders get an index generated by a script.

## One folder per project

```text
04-proyectos/<project>/
├── 00-contexto.md     goal, status, stack and the repo path
├── 01-decisiones/     why each thing was decided
├── 02-sesiones/       a summary of each work session
├── 03-pendientes.md   to-dos
├── 04-glosario.md     glossary
└── archivo/           full chats: they never enter the context
```

The repo path in `00-contexto.md` is the key: it tells which project applies based on the folder where I open Claude Code.

## The session-start hook

When each session starts, a Bash `SessionStart` hook:

1. reads the essential preferences;
2. finds the project whose path contains the current folder (if several match, the longest wins);
3. adds its to-dos and the recent items from `hot.md`;
4. trims everything to about 30 lines at most.

If anything fails, it exits silently. **An auxiliary tool must never block the session.**

## Seven skills

Everything else is on demand:

- **recall**: look things up before a task, or when an error "rings a bell".
- **capture**: save a bug with a non-obvious cause, a decision or a correction of mine.
- **session**: close a work session with its summary, to-dos and context.
- **ingest**: turn documentation or a PDF into linked notes.
- **interview**: ask me questions to fill in the gaps.
- **review**: maintenance, covering stale notes, finished to-dos and duplicate summaries.
- **audit**: read what I ask for in recent sessions and propose turning repeated tasks into skills.

## The golden rule: nothing without my permission

The agent **proposes** the exact text and I say yes or no. Every approved write is recorded in `log.md`. That keeps the brain free of noise and of things the agent thought it understood.

It also does not store what changes on its own, like CI status or issues: those are looked up live. A memory that lies is worse than no memory.

## Tooling with tests

Around it there are Python and Bash scripts, each with its own tests: the index generator, the read-only maintenance report and the exporter that archives chats in each project.

## Takeaways

- **A little context, well routed, beats a lot.**
- **Separate what is reusable from what belongs to one project**: a lesson about VA-API helps in any repo; a to-do only in its own.
- **The human decides what is remembered.** The agent proposes, I approve.
